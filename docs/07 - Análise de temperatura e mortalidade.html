Análise da associação entre temperatura e mortalidade utilizando modelos de defasagem distribuída não linear (DLNM)

Data de Publicação

31 de agosto de 2026

Introdução

Neste capítulo, vamos reproduzir parte da análise apresentada no artigo “Definição de marcadores térmicos associados à mortalidade para um sistema de alerta de calor extremo em Belo Horizonte, Minas Gerais, Brasil”.

Métodos

Área de estudo

O município de Belo Horizonte, localizado no Sudeste do Brasil, possui 331,4 km² e aproximadamente 2,3 milhões de habitantes.

Fontes de dados

Nesta análise, cada linha representa um dia. Para cada dia, temos o número de óbitos e informações sobre a temperatura.

Desfecho

Os dados de mortalidade foram obtidos do Sistema de Informação sobre Mortalidade (SIM), sendo extraídos os registros diários de óbitos por todas as causas no período de 2014 a 2024.

Exposição

Os dados meteorológicos são provenientes da rede de monitoramento do Instituto Nacional de Meteorologia (INMET), sendo selecionada a Estação Automática da Pampulha devido à sua representatividade espacial e altimétrica.

Análises estatísticas

Antes de ajustar o modelo, vamos conhecer os dados. Depois, construiremos aos poucos os elementos necessários para a análise.

Pacotes

O pacman é um pacote que facilita o gerenciamento de outros pacotes no R. Ele permite instalar e carregar vários pacotes de forma prática.

A instalação de um pacote é realizada apenas uma vez no computador. Por isso, esse comando deve ser executado na Session do Positron, e não como um bloco de código R no arquivo .qmd.

Para comparar as temperaturas em um mesmo gráfico, vamos primeiro reorganizar os dados. Atualmente, a base está no formato largo, em que cada tipo de temperatura ocupa uma coluna diferente (temp_min, temp_media e temp_max). Assim, uma mesma observação possui os três tipos de temperatura em colunas separadas.

No formato longo, cada linha representa uma combinação entre uma observação e um tipo de temperatura. Em vez de ter uma coluna para cada tipo de temperatura, passamos a ter uma coluna que identifica o tipo de temperatura e outra que contém o seu valor. Dessa forma, as temperaturas mínima, média e máxima passam a ser categorias de uma mesma variável.

A função pivot_longer() é utilizada para realizar essa transformação, facilitando a utilização dos dados em algumas análises e visualizações.

O boxplot é um gráfico utilizado para visualizar e comparar a distribuição de uma variável numérica.

  • A linha dentro da caixa representa a mediana, ou seja, o valor que divide os dados em duas partes iguais.
  • A caixa representa os 50% centrais dos dados, entre o primeiro e o terceiro quartil.
  • As linhas que se estendem a partir da caixa mostram a dispersão dos valores dentro de um determinado limite.
  • Os pontos além dos bigodes representam possíveis valores extremos (outliers).

Neste caso, cada caixa representa um tipo de temperatura: mínima, média e máxima, permitindo comparar suas distribuições.

Distribuição das temperaturas 
# Selecionar as variáveis de temperatura e transformar a base
dados_temp <- dados_brutos |>
  select(temp_min, temp_media, temp_max) |>
  pivot_longer(
    cols = everything(),
    names_to = "tipo",
    values_to = "temperatura"
  ) |>
  # Organizar os tipos de temperatura como categorias
  mutate(
    tipo = factor(
      tipo,
      levels = c("temp_min", "temp_media", "temp_max"),
      labels = c("Mínima", "Média", "Máxima")
    )
  )

# Criar o gráfico
grafico_temp <- ggplot(

Correlação

A correlação é uma medida que indica a intensidade e a direção da associação entre duas variáveis. O coeficiente de correlação varia de -1 a 1: valores próximos de 1 indicam uma associação positiva, valores próximos de -1 indicam uma associação negativa e valores próximos de 0 indicam pouca ou nenhuma associação.

Utilizaremos a correlação de Spearman, que é útil quando a relação entre as variáveis não é necessariamente linear ou quando os dados não atendem a alguns pressupostos da correlação de Pearson, como linearidade, ausência de outliers influentes e distribuição aproximadamente normal.

A matriz de correlação permite visualizar simultaneamente as associações entre todas as variáveis analisadas.

Matriz de correlação 
# Selecionar as variáveis e remover as colunas que não serão utilizadas
dados_correlacao <- dados_brutos |>
  select(
    -data,
    -obitos_infantil
  ) |>
  na.omit() |>
  sapply(as.numeric)

# Calcular as correlações de Spearman
cor_res <- rcorr(dados_correlacao, type = "spearman")
cor_matrix <- cor_res$r
p_values <- cor_res$P

# Criar os rótulos da matriz com duas casas decimais
# e um asterisco para correlações estatisticamente significativas
cor_text <- ifelse(
  !is.na(cor_matrix),
  paste0(
    formatC(cor_matrix, format = "f", digits = 1),
    ifelse(p_values < 0.05, "*", "")
  ),
  NA
)

# Substituir os valores da diagonal por 1.0
diag(cor_text) <- "1.0"

# Definir os nomes das linhas e colunas
colnames(cor_matrix) <- rownames(cor_matrix) <- colnames(dados_correlacao)
colnames(cor_text) <- rownames(cor_text) <- colnames(dados_correlacao)

# Manter apenas a metade inferior da matriz
cor_matrix[upper.tri(cor_matrix)] <- NA
cor_text[upper.tri(cor_text)] <- NA

# Transformar as matrizes em data frames para criar o gráfico
cor_df <- melt(cor_matrix, value.name = "value")
cor_text_df <- melt(cor_text, value.name = "label")

cor_df$label <- cor_text_df$label

# Criar o gráfico
grafico_correlacao <- ggplot(
  cor_df,
  aes(x = Var1, y = Var2, fill = value)
) +
  geom_tile(na.rm = TRUE) +
  geom_text(
    aes(label = label),

Preparação para o modelo

Agora vamos criar os objetos que o modelo precisa. Esta parte pode parecer mais técnica, mas a ideia central é simples: preparar uma forma adequada de representar tempo, temperatura e o possível atraso entre exposição e desfecho.

Estrato (strata)

A partir desta etapa, vamos criar uma nova versão da base chamada dados_modelo. A base dados_brutos será mantida sem alterações, enquanto dados_modelo será utilizada para adicionar variáveis necessárias ao modelo.

Antes de ajustar o modelo, precisamos criar uma variável de estrato. Neste estudo, os estratos serão definidos pela combinação de ano, mês e dia da semana.

Essa combinação permite comparar dias dentro de períodos semelhantes, ajudando a controlar diferenças entre meses, anos e dias da semana. Em outras palavras, o modelo compara dias que pertencem ao mesmo grupo de tempo.

A função paste() combina as informações de ano, mês e dia da semana em uma única variável. O argumento sep = ":" define o separador entre essas informações. Por fim, factor() transforma a variável em um fator, um tipo de variável utilizado no R para representar categorias ou grupos. Neste caso, cada combinação de ano, mês e dia da semana corresponde a um estrato diferente, que será utilizado no modelo.

Estratos 
dados_modelo <- dados_brutos |>
  mutate(
    strata = paste(
      ano,
      mes,
      wday(data, label = TRUE),
      sep = ":"
    ) |>
      factor()
  )

Splines e nós (knots)

Para estudar a relação entre temperatura e mortalidade, não vamos assumir que ela seja uma linha reta. Por exemplo, o risco pode ser diferente em temperaturas baixas, moderadas e altas.

Uma spline é uma função que permite representar uma relação não linear de forma flexível. Em vez de ajustar uma única linha reta para todos os valores de temperatura, a spline constrói uma curva formada por diferentes trechos, permitindo que ela acompanhe melhor os padrões observados nos dados.

  • Uma spline cúbica utiliza uma forma de curva que permite representar diferentes padrões de mudança na relação entre as variáveis. Os diferentes trechos são conectados de forma suave, formando uma única curva.

  • Uma spline cúbica natural funciona de forma semelhante a uma spline cúbica, mas possui algumas restrições nas extremidades da distribuição dos dados. Essas restrições fazem com que a curva tenha um comportamento mais simples nas extremidades, reduzindo a possibilidade de oscilações excessivas em regiões com poucos dados.

Os nós (knots) são pontos definidos ao longo dos valores de temperatura que determinam onde a curva pode mudar de comportamento. A quantidade e a posição dos nós influenciam o formato e a flexibilidade da curva.

Ou seja, a spline é a curva; os nós são os pontos que determinam onde essa curva pode mudar de comportamento.

Nesta análise, os nós serão definidos a partir de diferentes percentis da temperatura. Percentil é um ponto de referência na distribuição: por exemplo, o P90 é uma temperatura maior do que a observada em 90% dos dias. Vamos testar diferentes combinações para avaliar qual especificação representa melhor a relação entre temperatura e mortalidade.

A função quantile() é utilizada para calcular os valores correspondentes aos percentis escolhidos.

Nós para temperatura 
# Definir as combinações de percentis que serão utilizadas
percentis_knots <- list(
  # Percentis 10, 75 e 90
  # https://doi.org/10.1038/s41591-022-01872-6
  knots_10_75_90 = c(10, 75, 90),

  # Percentis 10, 50 e 90
  # https://doi.org/10.1038/s41591-023-02419-z
  knots_10_50_90 = c(10, 50, 90),

  # Percentis 25, 50 e 90
  # https://doi.org/10.1590/0102-311XEN042524
  knots_25_50_90 = c(25, 50, 90),

  # Percentis 50, 75 e 90
  knots_50_75_90 = c(50, 75, 90),

  # Percentis 50 e 90
  # https://doi.org/10.1016/j.envres.2024.119347
  # https://doi.org/10.3390/atmos16020196
  knots_50_90 = c(50, 90)
)

# Calcular os knots para a temperatura média
knots_media <- lapply(
  percentis_knots,
  \(x) {
    quantile(
      dados_modelo$temp_media,
      x / 100,
      na.rm = TRUE
    )
  }
)

# Calcular os knots para a temperatura máxima
knots_max <- lapply(
  percentis_knots,
  \(x) {

Nós de fronteira (boundary knots)

Além dos nós internos (knots), precisamos definir os nós de fronteira (boundary knots). Eles determinam os limites do intervalo em que a spline poderá apresentar um comportamento flexível.

Neste estudo, vamos definir os nós de fronteira como os percentis 1 e 99 da temperatura. Isso significa que o limite inferior será o valor de temperatura abaixo do qual estão 1% das observações, e o limite superior será o valor acima do qual estão 1% das observações.

Dentro desses limites, a spline pode representar a relação não linear entre temperatura e mortalidade. Fora deles, a spline cúbica natural é restrita a um comportamento linear. Essa estratégia reduz a influência de valores extremos e pouco frequentes na forma da curva.

Assim, temos três conceitos diferentes: os nós internos, que permitem mudanças no comportamento da curva; os nós de fronteira, que definem os limites do intervalo da spline; e a spline cúbica natural, que faz com que a curva assuma um comportamento linear nas regiões mais externas, além desses limites. Essa restrição evita que a curva fique excessivamente flexível nas extremidades, onde geralmente há menos observações e maior possibilidade de variações influenciadas por valores extremos.

Defasagens (lags)

Em estudos sobre os efeitos da temperatura na saúde, o efeito da exposição pode não ocorrer apenas no mesmo dia. Uma temperatura elevada pode estar associada a alterações na mortalidade nos dias seguintes.

A defasagem representa o número de dias entre a exposição à temperatura e o desfecho. Por exemplo, um período de lag_7 permite avaliar a associação desde o dia da exposição até 7 dias depois. Portanto, lag não é uma nova medida de temperatura: é uma forma de marcar o tempo desde a exposição.

Nesta análise, vamos testar diferentes períodos de defasagem, com base em intervalos utilizados em estudos anteriores.

Nós para as curvas de defasagem

Além de modelar de forma não linear a relação entre temperatura e mortalidade, também precisamos representar como esse efeito pode variar ao longo dos dias de defasagem.

Para isso, vamos utilizar nós na dimensão das defasagens. Serão testadas duas formas de posicionar esses nós:

  • logknots() distribui os nós de forma logarítmica, concentrando mais nós nos primeiros dias de defasagem. Essa configuração permite maior flexibilidade para representar efeitos que acontecem logo após a exposição.

  • equalknots() distribui os nós igualmente ao longo do período de defasagem, permitindo representar de forma mais uniforme possíveis efeitos que se distribuem ao longo dos dias.

Em ambos os casos, utilizaremos 3 nós para cada período de defasagem.

Modelo DLNM

Até aqui, descrevemos separadamente a curva da temperatura e a curva do tempo de defasagem. O DLNM combina as duas para responder à pergunta completa: como a associação muda conforme a temperatura e conforme passam os dias?

Cross-basis: combinação de temperatura e defasagem

Agora vamos combinar as duas dimensões que estamos estudando: a temperatura e o tempo de defasagem (lag).

No contexto dos modelos de defasagem distribuída não linear (Distributed Lag Non-Linear Models – DLNM), essa combinação é chamada de cross-basis. Ela permite representar simultaneamente duas características da associação entre temperatura e mortalidade: como a associação varia de acordo com a temperatura e como o efeito pode se distribuir ao longo dos dias de defasagem após a exposição.

Para a temperatura, utilizaremos uma spline cúbica natural, com os nós definidos anteriormente e os nós de fronteira nos percentis 1 e 99. Para a defasagem, também utilizaremos uma spline cúbica natural, com os nós definidos por logknots() ou equalknots().

A função crossbasis() do pacote dlnm combina essas duas dimensões em uma estrutura que poderá ser incluída posteriormente no modelo estatístico.

O argumento argvar define como a temperatura será modelada, enquanto arglag define como as defasagens (lags) serão modeladas. O argumento fun = "ns" indica que será utilizada uma spline cúbica natural.

Como estamos avaliando diferentes combinações de nós, períodos de defasagem e formas de distribuição dos nós das defasagens, vamos criar vários cross-basis. Eles serão armazenados separadamente para a temperatura média e para a temperatura máxima.

Cross-basis 
# Criar listas para armazenar os cross-basis separadamente
cbs_media <- list()
cbs_max <- list()

# Definir as temperaturas que serão analisadas
temperaturas <- list(
  temp_media = list(
    dados = dados_modelo$temp_media,
    knots = knots_media,
    boundary = boundary_media_1_99
  ),
  temp_max = list(
    dados = dados_modelo$temp_max,
    knots = knots_max,
    boundary = boundary_max_1_99
  )
)

# Criar os cross-basis para cada temperatura, período de lag e distribuição dos knots dos lags.
for (temp_name in names(temperaturas)) {
  temp_info <- temperaturas[[temp_name]]
  for (knots_name in names(temp_info$knots)) {
    pred_knots <- temp_info$knots[[knots_name]]
    for (lag_name in names(lags)) {
      n_lag <- lags[[lag_name]]
      for (tipo_lag in c("logknots", "equally")) {
        lag_knots <- if (tipo_lag == "logknots") {
          lags_knots_3[[paste0(lag_name, "_knots_3")]]
        } else {
          lags_knots_3_equal[[paste0(lag_name, "_knots_3_eq")]]
        }
        cb <- crossbasis(
          temp_info$dados,
          lag = n_lag,
          argvar = list(
            fun = "ns",
            knots = pred_knots,
            Boundary.knots = temp_info$boundary
          ),
          arglag = list(
            fun = "ns",
            knots = lag_knots,
            intercept = TRUE
          )
        )
        cb_name <- paste(
          temp_name,
          knots_name,
          lag_name,
          tipo_lag,
          sep = "_"
        )
        # Armazenar o cross-basis na lista correspondente
        if (temp_name == "temp_media") {
          cbs_media[[cb_name]] <- cb
        } else {
          cbs_max[[cb_name]] <- cb
        }
      }
    }
  }
}

Ajuste dos modelos

Depois de criar os cross-basis, vamos utilizá-los nos modelos estatísticos para investigar a associação entre temperatura e mortalidade. Como estamos testando várias escolhas, cada combinação gera um modelo diferente.

Neste estudo, utilizaremos um CP-DLNM (Conditional Poisson Distributed Lag Non-Linear Model, ou modelo de Poisson condicional com defasagem distribuída não linear). O termo condicional está relacionado à utilização da variável strata, criada anteriormente a partir da combinação de ano, mês e dia da semana. Essa estratégia permite controlar a sazonalidade e a variação associada aos dias da semana, comparando os dias dentro dos mesmos estratos.

Cada linha da base representa um dia da série temporal, e o número de óbitos observados nesse dia é a variável de desfecho. Como se trata de uma variável de contagem, utilizaremos um modelo quasi-Poisson, que permite considerar a superdispersão, situação em que a variabilidade observada no número de óbitos é maior do que a esperada pelo modelo de Poisson.

O ajuste dos modelos será realizado com a função gnm() do pacote gnm, utilizada para ajustar modelos lineares generalizados e modelos com estruturas mais complexas. No nosso caso, o gnm() permite incluir o cross-basis como variável explicativa e utilizar strata no argumento eliminate, controlando os efeitos associados aos estratos sem precisar estimar um coeficiente separado para cada estrato.

Como estamos avaliando diferentes combinações de nós, períodos de defasagem e formas de distribuição dos nós das defasagens, serão ajustados vários modelos. Os modelos serão armazenados em listas separadas para a temperatura média e para a temperatura máxima, facilitando sua organização e posterior comparação.

Ao utilizar summary() em um modelo, o R apresenta informações sobre o ajuste, como os resíduos de deviance, os coeficientes estimados, seus erros-padrão, valores de teste e níveis de significância, além da estimativa de dispersão do modelo. Os coeficientes apresentados como cbv1.1, cbv1.2, entre outros, correspondem aos diferentes componentes do cross-basis e não devem ser interpretados isoladamente. A interpretação da associação entre temperatura e mortalidade será feita posteriormente a partir dos resultados derivados do modelo.

Ajuste dos modelos 
# Listas para armazenar os modelos separadamente
modelos_media <- list()
modelos_max <- list()

# Ajustar os modelos para cada temperatura
for (tipo_temp in c("media", "max")) {
  # Selecionar os cross-basis correspondentes à temperatura
  cbs <- if (tipo_temp == "media") {
    cbs_media
  } else {
    cbs_max
  }
  # Ajustar um modelo para cada cross-basis
  for (cb_name in names(cbs)) {
    # Recuperar o cross-basis
    cb <- cbs[[cb_name]]
    # Ajustar o modelo
    mod <- gnm(
      obitos_total ~ cb,
      eliminate = strata,
      family = quasipoisson(),
      data = dados_modelo
    )
    # Armazenar o modelo na lista correspondente
    if (tipo_temp == "media") {
      modelos_media[[cb_name]] <- mod
    } else {
      modelos_max[[cb_name]] <- mod
    }
  }
}

Comparação dos modelos

Até aqui, criamos diferentes modelos variando os nós da temperatura, os períodos de defasagem e a forma de distribuição dos nós das defasagens. Agora vamos comparar essas diferentes especificações para identificar quais apresentam melhor ajuste aos dados.

Como estamos utilizando modelos quasi-Poisson, utilizaremos o QAIC (Quasi-likelihood Akaike Information Criterion), um critério de informação adequado para comparar modelos que consideram a superdispersão.

O QAIC considera tanto o ajuste do modelo aos dados quanto sua complexidade. De forma geral, valores menores de QAIC indicam modelos preferíveis entre as especificações comparadas, pois representam um melhor equilíbrio entre ajuste e complexidade.

Assim, vamos utilizar o QAIC para comparar todas as combinações de nós, períodos de defasagem e formas de distribuição dos nós das defasagens. O QAIC ajuda a escolher uma especificação, mas não substitui a avaliação científica da pergunta, da qualidade dos dados e da plausibilidade do modelo.

A referência utilizada para o uso do Q-AIC na seleção da especificação do modelo é: https://doi.org/10.1186/1476-069X-11-63

Comparação dos modelos 
# Calcular o QAIC manualmente
qaic_manual <- function(mod) {
  dev <- deviance(mod)
  phi <- summary(mod)$dispersion
  k <- length(coef(mod))
  dev / phi + 2 * k
}

# Função para calcular o QAIC de todos os modelos
avaliar_modelos <- function(modelos, temperatura) {
  resultados <- data.frame(
    modelo = names(modelos),
    QAIC = NA_real_,
    temperatura = temperatura
  )
  for (i in seq_along(modelos)) {
    mod <- modelos[[i]]
    resultados$QAIC[i] <- qaic_manual(mod)
  }
  resultados
}

# Avaliar os modelos de temperatura média e máxima
resultados_media <- avaliar_modelos(
  modelos_media,
  temperatura = "Média"
)
resultados_max <- avaliar_modelos(
  modelos_max,
  temperatura = "Máxima"
)

# Juntar os resultados
resultados <- bind_rows(
  resultados_media,
  resultados_max

  arrange(QAIC)

# Calcular o delta-QAIC

  mutate(
    delta_QAIC = QAIC - min(QAIC)

  mutate(

      grepl("knots_10_75_90", modelo) ~ "P10, P75 e P90",
      grepl("knots_10_50_90", modelo) ~ "P10, P50 e P90",
      grepl("knots_25_50_90", modelo) ~ "P25, P50 e P90",
      grepl("knots_50_75_90", modelo) ~ "P50, P75 e P90",

Modelo selecionado e predições

Até aqui, ajustamos diferentes especificações do modelo, variando os nós da temperatura, os períodos de defasagem e a forma de distribuição dos nós das defasagens. A comparação pelo QAIC permitiu avaliar o ajuste dessas diferentes especificações e selecionar o modelo utilizado nas etapas seguintes.

Nesta análise, vamos trabalhar com o modelo temp_max_knots_50_90_lag_21_equally, que utiliza a temperatura máxima, nós nos percentis 50 e 90, um período de 21 dias de defasagem e nós igualmente espaçados na dimensão das defasagens. Essa especificação foi selecionada com base no QAIC, enquanto a utilização da temperatura máxima segue a estratégia apresentada no artigo que estamos reproduzindo.

A partir desse modelo, vamos utilizar a função crosspred() do pacote dlnm para gerar as associações estimadas entre temperatura e mortalidade. Os resultados serão expressos como risco relativo (RR), que compara o risco estimado de mortalidade para uma determinada temperatura com o risco correspondente à temperatura utilizada como referência. Um RR igual a 1 indica o mesmo risco da temperatura de referência; valores maiores que 1 indicam maior risco e valores menores que 1, menor risco.

Nesta etapa, a predição será utilizada para identificar a temperatura associada ao menor risco relativo estimado, que será posteriormente utilizada como temperatura de mortalidade mínima (MMT). O modelo também permite estimar o efeito cumulativo, que representa a associação acumulada ao longo dos 21 dias de defasagem.

NotaComo interpretar a MMT

A MMT é uma estimativa produzida pelo modelo, e não necessariamente uma temperatura “segura” ou uma temperatura que elimine o risco. Ela representa o ponto de menor risco relativo estimado dentro da curva e pode variar conforme os dados, o período estudado e a especificação do modelo.

Preparando a curva cumulativa

Antes de identificar a MMT, precisamos recuperar o modelo selecionado e calcular a curva cumulativa. Nesta curva, cada temperatura é comparada inicialmente com a mediana da temperatura máxima.

Curva cumulativa usada para estimar a MMT

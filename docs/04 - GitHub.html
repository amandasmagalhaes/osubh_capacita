Git, GitHub e Positron

O GitHub é uma plataforma online para armazenar e compartilhar projetos, acompanhar alterações e colaborar com outras pessoas.

Antes de utilizá-lo, é importante diferenciar três ferramentas que trabalham em conjunto:

Ferramenta Para que serve
Git Sistema de controle de versão que registra o histórico das alterações em um projeto.
GitHub Plataforma online que hospeda repositórios Git e permite compartilhar e sincronizar projetos.
Positron Ambiente de desenvolvimento onde criamos e editamos arquivos e utilizamos os recursos do Git.

Evite enviar senhas, chaves de acesso ou outras informações sensíveis para o repositório. Antes de realizar um commit, revise os arquivos modificados para garantir que apenas as alterações desejadas serão registradas.

Criar uma conta no GitHub

  1. Acesse github.com.
  2. Digite seu endereço de e-mail e clique em Cadastrar-se no GitHub.
  3. Preencha as informações solicitadas e siga as etapas de criação da conta.
  4. Confirme o endereço de e-mail cadastrado.
  5. Faça login na sua conta.
Dica

Escolha um nome de usuário simples e fácil de identificar. Ele fará parte do endereço dos seus repositórios. Por exemplo: https://github.com/seu-usuario/meu-projeto.

Mais informações estão disponíveis na documentação oficial sobre criação de contas no GitHub.

Instalar o Git

No Windows, normalmente é necessário instalar o Git separadamente. No macOS e em algumas distribuições Linux, ele pode já estar disponível. Caso o Git já esteja instalado, esta etapa pode ser ignorada.

Acesse a página oficial de instalação do Git e selecione o sistema operacional do seu computador:

  • Windows
  • macOS
  • Linux

Após a instalação (ou para verificar se o Git já está disponível), abra o terminal integrado do Positron e execute:

git --version

Se uma mensagem semelhante a git version 2.x.x for exibida, significa que o Git está instalado e pronto para uso.

Configurar seu nome e e-mail

Essa configuração é realizada apenas uma vez em cada computador.

Utilize o seu nome completo e o mesmo endereço de e-mail cadastrado e confirmado no GitHub.

Abra o terminal integrado do Positron e execute os comandos abaixo:

git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

Para verificar se a configuração foi realizada corretamente, execute:

git config --global --list

Se tudo estiver correto, serão exibidas informações semelhantes a:

user.name=Seu Nome
user.email=seu-email@exemplo.com

Criar um repositório no GitHub

Um repositório (repository ou repo) é o local onde ficam armazenados os arquivos de um projeto e o histórico de todas as alterações realizadas.

  1. Acesse github.com/new.
  2. Em Repository name, informe um nome para o repositório, por exemplo “primeiro_projeto”.
  3. Em Description, escreva uma breve descrição, se desejar.
  4. Em Choose visibility, escolha Public para tornar o repositório visível para qualquer pessoa ou Private para restringir o acesso apenas às pessoas autorizadas.
  5. Em Start with a template, mantenha No template.
  6. Marque a opção Add a README file.
  7. Em Add .gitignore, selecione R.
  8. Em Add license, mantenha No license.
  9. Clique em Create repository.

Arquivos criados automaticamente

Ao criar o repositório, dois arquivos serão adicionados automaticamente.

README.md

O arquivo README.md é a página inicial do repositório. Ele contém uma descrição do projeto e orientações para quem irá utilizá-lo ou contribuir com seu desenvolvimento.

É recomendado incluir o objetivo do projeto, a estrutura dos principais arquivos e pastas, as instruções de uso e, quando necessário, informações sobre autoria e contato. Como o README é exibido automaticamente na página inicial do GitHub, ele funciona como a documentação principal do projeto.

.gitignore

O arquivo .gitignore informa ao Git quais arquivos e pastas devem ser ignorados e, portanto, normalmente não serão versionados. Ao selecionar o modelo R, o GitHub cria automaticamente um arquivo com regras apropriadas para projetos desenvolvidos nessa linguagem.

Em geral, arquivos temporários, arquivos de configuração local, caches e logs não devem ser incluídos no repositório.

Importante: o .gitignore só impede que arquivos ainda não versionados sejam adicionados ao Git. Ele não remove dados sensíveis que já tenham sido enviados ao repositório. Nesse caso, é necessário removê-los do histórico e, se for o caso, revogar ou substituir as senhas e chaves de acesso.

Abaixo é apresentado um exemplo simplificado. O arquivo .gitignore pode ser editado a qualquer momento para incluir ou remover regras conforme as necessidades do projeto.

# Arquivos temporários do R
.Rhistory
.RData
.Ruserdata
.Rproj.user/

# Arquivos temporários do Python
__pycache__/
*.pyc

# Configurações locais do Positron / VS Code
.vscode/

# Arquivos temporários do Quarto
.quarto/
*_cache/
**/*.quarto_ipynb

# Arquivos de log
*.log

# Dados
*.csv
*.xlsx
*.dta
*.rds
*.rda
*.sav

Abrir um repositório no Positron

Agora vamos clonar o repositório criado no GitHub para o computador utilizando o Positron.

  1. No GitHub, acesse o repositório criado.
  2. Clique em Code e copie a URL do repositório.
  3. Abra o Positron.
  4. Selecione New > New Folder from Git.
  5. Cole a URL no campo Git repository URL.
  6. Em Create folder as subfolder of, escolha a pasta onde o projeto será salvo.
  7. Clique em OK.
  8. Aguarde a clonagem. O Positron abrirá automaticamente a pasta do projeto.

Após a clonagem, todos os arquivos do projeto estarão disponíveis no computador. A partir desse momento, qualquer alteração realizada poderá ser sincronizada com o GitHub por meio do Git.

Adicionar arquivos e fazer um commit

Como o repositório foi criado com um README.md e um .gitignore, ele já possui um commit inicial. Depois de clonar o repositório, adicione ou copie os arquivos do projeto para a pasta clonada.

Um commit registra um conjunto de alterações no histórico local do Git. Nessa etapa, as alterações ainda não são enviadas para o GitHub.

Na aba Source Control:

  1. Confira a lista de arquivos em Changes.

  2. Escreva uma mensagem que descreva as alterações realizadas, por exemplo:

    Adiciona arquivos iniciais do projeto

  3. Clique em Commit.

  4. Clique em Push ou Sync Changes para enviar as alterações ao GitHub.

A mensagem do commit deve ser curta e descrever claramente o que foi feito.

Evite mensagens genéricas, como mudanças, teste ou atualização, pois elas dificultam a compreensão do histórico do projeto.

Resumo

  • Commit: registra as alterações no histórico local do projeto.
  • Push: envia os commits locais para o GitHub.
  • Pull ou Sync Changes: atualiza o projeto local com as alterações existentes no GitHub.
